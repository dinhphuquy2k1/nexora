## Selected test discovery and command design

Keep Turbo workspace delegation and its test dependsOn build/cache=false behavior. An ordinary suite is environment-safe when it needs no externally provisioned service, deployment credentials or destructive infrastructure; loopback HTTP and owned temporary files/processes used by existing unit/functional tests remain allowed. Frozen dependencies and genuine build/Prisma artifacts are still prerequisites; environment-safe does not mean dependency-free or offline-buildable. Preserve genuine database/shared/API/Web build ordering and API_INTERNAL_URL requirements; never fabricate artifacts to satisfy it.

Use quoted native Node glob arguments, expanded by Node rather than shell. API ordinary: node --test 'test/**/\*.test.cjs'; Web/database/UI ordinary: node --test 'test/**/\*.test.mjs'. No blanket node --test over the entire repository and no discovery of arbitrary .cjs/.mjs/.ts. Helpers/fixtures must not end in .test.cjs/.test.mjs; TypeScript contract fixtures compile through their existing owners and are not direct Node suites. A helper directory is not a security boundary if its files carry test suffixes: document and regression-test this convention. New ordinary nested tests require no package-script changes.

Move exactly the eight existing API integration suites to apps/api/integration/ retaining their basenames; keep ordinary26 files, including test/infrastructure/identity.test.cjs, in place. API integration: node --test 'integration/\*_/_.test.cjs'. This sibling root avoids a custom exclusion runner and permits future nested ordinary discovery. Adjust only move-induced relative dist/helpers/source references; preserve every assertion, fixture, timeout, DB/role guard and lock-wait observation. Do not split/rewrite Customer's shared-state HTTP scenario. Integration remains an explicit approved-environment command; moving files does not authorize arbitrary DATABASE_URL targets.

Root pnpm test becomes node --test 'scripts/\*_/_.test.mjs' && turbo run test. Root tooling tests (docs, lint rules, governance, smoke-check policies and future controlled launcher regressions) are ordinary tests; real smoke launchers remain .mjs without .test suffix and are never included. pnpm quality keeps format, lint, static preflight, docs validation, typecheck, pnpm test, contracts and build; remove redundant explicit tooling-test calls there because pnpm test includes them once. Keep test:lint/test:preflight/test:docs/test:operations as purposeful targeted compatibility aliases using category globs or existing single entrypoint, not feature proliferation. Dedicated Preflight workflow still runs its focused tests separately from Foundation intentionally: independent low-privilege approval gate, not duplicate execution within quality.

Root test:integration continues delegating to API, specialized migration/disposable cluster/smoke commands remain separate. No test:all. Remove API test:customer alias and its otherwise-unused tsconfig.customer-tests.json only after replacing callers/docs with the normal build-backed test path; do not remove assertions or the full-build prerequisite. Native database test:customer:sql and test:provision:cluster may remain compatibility selectors for materially different dangerous suites under the same owned launcher; they are not ordinary feature test commands. SDK/shared currently have no test scripts; do not add empty suites solely for uniformity.

Preserve bounded commands/readiness and add signal/failure cleanup equivalence tests.
- scripts/provision-cluster-smoke.py -> same-stem .mjs using async child processes, crypto randomness, monotonic performance clock and bounded polling. Keep strict --suite=provision/customer-sql semantics, unique network/container names and labels, IDs plus database signature, no published PG ports, real TCP SELECT1 before signature and from tooling network before suite DDL, isolated suite containers/mounts, exact exit and timeout handling. Keep registry of pending creates and owned IDs; recover timed-out creation only after label/ID verification; inspect permission/parse/daemon errors never prove absence; verify deletion before final PASS. Preserve original failure alongside cleanup failure and redaction of passwords/tokens/URLs/SQL payloads. SIGINT/SIGTERM request termination, await in-flight create bookkeeping, stop attach, perform one bounded finally cleanup, exit128+signal. Unknown ownership fails closed without deleting an unverified resource. Do not import business common validators into host tooling; existing run-token/ownership checks are launcher-specific protocols.
- scripts/provision-cluster-smoke.test.py -> same-stem .test.mjs, port every existing controlled-Docker scenario to node:test, with test-owned executable fixture and state. Preserve partial create/recovery, TCP-only readiness, stopped/ownership invalid, attach vs container status, malformed/permission inspect, cleanup failure, original+cleanup failure, selectors, signals and no-prune assertions. Port fixture executable itself to Node so Python is not secretly retained by these tests. Controlled fixtures do not prove PostgreSQL; real suites remain mandatory.
- scripts/provisioning-tty-smoke.py and scripts/mfa-enrollment-tty-smoke.py: RETAIN narrowly justified Python standard-library PTY exception. Node standard library lacks openpty/termios; shell script utilities are not established equivalents for capture/echo/cancellation/restoration and MFA commit-before-code/rollback checks. Do not replace with piped stdin/mocks or native addons. Their callers, real PTY assertions, Ctrl+C/EOF/backspace/prompt/terminal restoration and mode0600 fixture handling remain intact. Python3 remains a documented host prerequisite for these two harnesses; tools Docker image currently does not install Python and gains no new dependency.
- scripts/public-https-smoke.sh embedded Python port allocation, safe diagnostic classification and owned temporary cleanup -> Node built-in net/fs/path operations, preserve loopback-only listeners, bounded safe output and canonical physical path ownership. Port allocation still has a close-to-bind race; do not claim reserved ports or weaken TLS checks. Existing openssl/cert replacement/remote browser assertions and PTY Python caller remain unchanged.

Use small script-local functions or a narrowly shared bounded-child-process helper only where truly duplicated by the three Node launchers; no generic orchestration/configuration/plugin framework. Reuse Docker CLI, existing Compose, SQL suites, provision-runtime.mjs and runtime-privilege-assertions.mjs. Do not centralize distinct domain authorization or transaction policy.

## Alternatives and risks

Reject broad default discovery (would include unsafe integration/destructive harnesses), negative filename lists (future omission risk), flattening all tests (unnecessary churn), external glob/test libraries or custom runner (built-in glob suffices), blanket Python removal (weakens genuine PTY coverage), and migration of complex harnesses without failure-equivalence tests (ownership/cleanup risk). Sibling integration relocation is limited8-file churn to establish a structural boundary; ordinary tests remain where they are.

High risks: orphaned resources after signals/timeout, cleanup of unowned IDs, lost original exit/redaction, accidental integration in ordinary tests, omitted/double suites and broken relative imports/build prerequisites. Mitigate with characterization manifest, isolated fixtures, exact membership/negative ownership/signal tests and real Docker/PG runs. Medium risks: inherited GitHub event/environment leakage, shared dist writes/watchers, slow browser/dev startup and port races. Preserve explicit environment override semantics, serialize fixture env edits, stop watchers through existing quality orchestration and report actual failing phase. Do not expand this task into unrelated timeout/runtime fixes without reproduction and a scoped approved amendment.

Rollback: focused milestone commits; revert callers together with their matching implementation/test/documentation changes, keeping old harness until equivalent positive/negative/genuine tests pass. Never run both real launchers concurrently against shared resources. No history rewrite, user-volume reset or broad Docker prune. If equivalence fails, stop and retain Python implementation for that harness rather than delete assertions.
