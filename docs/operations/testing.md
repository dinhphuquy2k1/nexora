# Testing

`sh scripts/quality-docker.sh` starts development mode, then runs frozen-installed formatting, architectural lint, typecheck, meaningful unit tests, contract drift, build and migrated PostgreSQL integration inside Docker. It pauses API/web watchers while build outputs are rewritten, restarts them on exit and does not delete volumes. Use the `run` mapped-user entrypoint for commands writing generated outputs rather than bypassing it with exec.

```sh
docker compose -f compose.yml -f compose.dev.yml run --rm --no-deps -T api sh /workspace/scripts/api-entrypoint.sh sh -c 'NODE_ENV=production API_INTERNAL_URL=http://api:4000 pnpm quality && NODE_ENV=test pnpm test:integration'
sh scripts/runtime-smoke.sh
sh scripts/data-smoke.sh
sh scripts/dev-smoke.sh
```

Runtime smoke creates its own disposable project and checks real proxy health/errors, non-root runtime, DB outage, repeated migration, and the complete authentication lifecycle (Host header filtering, untrusted Origin rejection, unauthenticated route rejection, safe malformed cookie parsing, login credential verification, session cookie issuance, session validation, and post-logout revocation). Data smoke stores a real catalog row + file, verifies down/up and service restart persistence in distinct disposable volumes, then removes ONLY those volumes. Dev smoke verifies HMR/shared propagation and frozen dependency failure without resetting DB. Stop unrelated web occupying port 3001 first.
Host `pnpm quality` is optional and needs working engine downloads; it is not a substitute for Docker runtime verification. Contracts can generate without DB or engine; built web consumes existing generated output.
CI `.github/workflows/foundation.yml` runs Docker quality/runtime/data/dev smoke on Linux. A created workflow is NOT VERIFIED until a hosted run exists. See the task ledger for actual commands, counts and limitations.

Cloud-only overrides may be supplied as `NEXORA_COMPOSE_OVERRIDE=/absolute/path/platform.yml`. Set `NEXORA_QUALITY_NO_BUILD=1` only when matching dev/migration images were already built and verified; the default builds images. Neither option skips quality or integration checks.

The authentication runtime smoke now provisions fresh operators through `dist/cli/user-create.js --password-stdin` via the runtime entrypoint, verifies duplicate rejection, and runs `scripts/provisioning-tty-smoke.py` against the same compiled non-root image. The pseudo-TTY harness uses Python standard-library PTY facilities, checks hidden password/confirmation, Enter, Backspace, Ctrl+C/Ctrl+D and both container/host terminal restoration without printing captured output.

`scripts/auth-runtime-smoke.mjs` exercises the actual Web proxy: exact/missing/wrong Origin, invalid JSON fields, fake/malformed/expired sessions, cookie attributes under forged forwarding headers, persistence across API restart, idempotent logout, safe logout failure and fail-closed workspace access during a disposable PostgreSQL outage followed by recovery. It additionally asserts standalone public `/login` rendering (no AppShell), unauthenticated/stale session redirection (`/login?from=...`), and valid session workspace access. `scripts/browser-login-smoke.mjs` uses Chromium DevTools with Node's built-in WebSocket to verify standalone Login layout (no AppShell headers/navigation), unauthenticated workspace redirection, typing and submitting the real Login form, observing the response, verifying HttpOnly session and authenticated AppShell presence on protected navigation, and post-logout revoked session redirection. It adds no npm browser framework. Host smoke requires Node >=22, Python 3 and installed Chrome/Chromium (or CHROME_BIN); missing browser support fails instead of silently skipping. Existing foundation CI selects pinned host Node 24.19.0 and invokes these through runtime smoke. Credentials arrive by stdin and are never emitted in diagnostics.

`NEXORA_COMPOSE_OVERRIDE` also applies to runtime smoke, allowing the same cloud CA build-secret setup as quality. Run with a different loopback WEB_PORT to exercise port derivation without publishing API/database. All destructive expiry/outage/cleanup steps are limited to the disposable project's own data. Source changes and historical CI do not establish that these expanded checks passed; current evidence and gaps remain in NEXORA-009.

Authentication HTTP smoke uses stable diagnostic step IDs with only expected/actual status and sanitized failure categories. The Host-negative check uses `node:http`, because Node 24 fetch rewrites Host and cannot establish that an untrusted Host reached middleware. No response payload, cookie/token, request body or raw assertion/driver exception is printed. `pnpm test:operations`, included in quality, exercises this transport and smoke check diagnostics behavior.

Phase 1 quality additionally executes `pnpm --filter @nexora/database test:migrations` inside the existing Docker quality runner. It creates/drops only fresh UUID-named databases, deploys authentic baseline migrations, injects failure into a temporary copy/config, compares application schema/data rollback separately from Prisma metadata, resolves the failed attempt through Prisma, deploys unmodified SQL, verifies constraints/defaults/cascades/repeated deploy and schema drift. Driver/assertion details and credential values are suppressed on failure. In Phase 2, migration tests verify `20261012020000_external_identities`: compound unique constraints `(provider, provider_subject)` and `(user_id, provider)`, provider check constraint (`uniship`), subject format check constraint, and cascade deletion.

Real API integration fixtures prove ACTIVE Operator sessions without credentials, credentialless/Operator local Login rejection, disabled/expired/revoked session rejection, explicit atomic ADMIN CLI provisioning, fake-provider Uniship external identity authentication, duplicate subject database rejection, SessionGuard integration, independent-session Logout, and end-to-end provider login orchestration against an isolated local HTTP mock provider (`apps/api/test/integration.test.cjs`). Unit suites (`apps/api/test/provider-auth.test.cjs`, `apps/api/test/unit.test.cjs`) test `UnishipAuthAdapter` URL safety, production HTTPS enforcement, operational live-call gating, mock HTTP status/malformed payload/timeout/redirect handling, `AuthService.loginWithProvider` admission rate limiting with per-provider lockout isolation, `IdentityDatabaseAdapter.findExternalIdentity` compound queries, and `loadConfig` normalization of empty/absent provider URLs, protocol restrictions (HTTP/HTTPS only), and authorization flag validation. Chromium browser smoke harness (`scripts/browser-login-smoke.mjs`) tests both Employee mode (`/login` targeting `/api/auth/provider/login`) and Admin mode (`/login?mode=admin` targeting `/api/auth/login`), confirming form rendering, endpoint routing, provider failure handling, and Admin login isolation. Data smoke verifies database catalog and stored file persistence across service restart and `docker compose down` / `up` cycles. These are executable tests, not verification until command/CI evidence exists.

The canonical `sh scripts/quality-docker.sh` also runs `python3 scripts/sql-registration-smoke.py` (host Python 3 standard library and Docker, already required by runtime smoke). The harness creates a uniquely named PostgreSQL 17.11 container with no published ports and `--network none`; it uses no configured installation connection or existing volume. Readiness checks TCP on container loopback, so the image's temporary Unix-socket-only initialization server cannot be mistaken for the final PostgreSQL listener. It applies unmodified committed migration DDL to the disposable schema, copies and SHA-256 checks the actual registration file, and executes `psql -X -v ON_ERROR_STOP=1 -v username=... -v uniship_userid=... -f` for every registration. This tests the operator-facing script; the separate Prisma migration suite remains authoritative for deployment metadata and drift.

The real SQL matrix asserts successful ACTIVE OPERATOR plus matching identity and zero credentials; duplicate username/subject rollback; input rejection and accepted length boundaries; quotes/SQL-like literal safety and Unicode under existing policies; forced second-insert rollback; and two independent connections racing on the same subject, synchronized after preflight through a test-owned advisory-lock trigger. Exactly one succeeds and the loser leaves no user. ADMIN rows, credentials and sessions are compared privately throughout. Cleanup removes only the newly created test container and its anonymous volume; diagnostic output contains stage labels, never raw SQL inputs, database snapshots or driver exceptions. The original file failed this same harness before the psql-variable fix.

Uniship API integration authorization is owner-confirmed (2026-10-13). Existing local mock-provider PASS covers executable authentication behavior, not live Uniship technical verification. This regression harness makes no external provider requests and does not enable `UNISHIP_LIVE_AUTHORIZED`.

`node --test apps/web/test/launcher.test.mjs` is included in the Web package test command and canonical quality. It exercises the real dev/start entrypoints against a disposable Next CLI fixture, using randomly allocated ports. Coverage includes canonical host/Docker/custom port parsing and boundaries; malformed/empty PORT; command/argument/environment propagation; normal/nonzero/signal child exit codes; sanitized actual spawn failure; occupied-port refusal without fallback or damage to the existing listener; a real EADDRINUSE after preflight; and SIGINT/SIGTERM/SIGHUP forwarding, child exit and released ports. These focused process tests supplement real Next.js HMR/runtime/browser smoke rather than replacing it.

Provider vocabulary is feature-local `IdentityProvider.UNISHIP`; existing adapter, service and compound-key database tests assert the unchanged literal wire/storage value `uniship`, unsupported-provider rejection and disabled/unregistered identity failures. No database migration or HTTP/SDK contract is changed. The repaired SQL file and its canonical real-psql smoke remain unchanged and continue to run in quality.
