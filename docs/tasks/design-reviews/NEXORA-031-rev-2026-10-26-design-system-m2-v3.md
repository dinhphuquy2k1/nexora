## 6. Alternatives and tradeoffs

Owner decisions (32/40/48, no stats hook/request, colgroup/Skeleton/Toast/single-flight/standard-wide) are fixed. Rejected mechanisms: feature-local --control-height shadows (hide root changes), global 44px compatibility mode (contradicts direction), new UI/state/test dependencies (no need), copying ZIP mock timing/data (incorrect product), retaining unkeyed rows/stats (wrong query/owner), and LayoutProvider or relocating every route merely to set gutters (unnecessary complexity).

Select CSS data-size mapping with private component aliases rather than inline literal heights: public root values remain runtime authoritative. Select a small shared emphasis color variant instead of changing Login/MFA colors globally; the accessible color tradeoff is explicit below. One parser context-resolution extension is preferable to separate regex enforcement or blanket token allowlists.

## 7. Selected design and interfaces

### A. Shared controls and three token layers

Foundation owns existing scales/palette; semantic aliases own text/action/surface/gutter roles; UI component mappings own size/state application. Do not duplicate scales or give Customer its own control height. Root public height tokens: --control-size-default:32px, --control-size-medium:40px, --control-size-large:48px. Omitted size is default. Height and minimum-height resolve through the selected public token at the actual component, never through inherited, already-resolved44px aliases. Remove --control-height after migrating every production/test consumer; no hidden legacy fallback or supported feature-level override. Retain public --control-radius and --control-font-size (default existing13px body/label scale), and documented semantic control state/color overrides. Radius default8px from existing scale, not a new radius scale.

Export ControlSize = default | medium | large and typed props from @nexora/ui. Button/TextInput/Select/Textarea/Checkbox accept optional size; Input/Select props omit the native numeric size field before adding this union. No current numeric-size consumer exists; no unused nativeSize escape hatch is added. Preserve rows/multiple/type native semantics where applicable; do not force a multi-select into one-line height. Use React19 native ref props (ComponentPropsWithRef) so current Header/dialog triggers retain real element identity; do not introduce another focus abstraction.

One-line default/medium/large heights32/40/48, horizontal padding12/16/20 (existing spacing3/4/5), icon14/16/18 semantic sizes,1px border, existing focus2px/offset2px. Shared Button/Input/Select use the same mapping and font/box-sizing. Generic private --\_control-\* mappings may be declared only in UI component scopes and must resolve to public tokens; parser validates ownership/references, not an exemption for arbitrary private names. Actual SVGs consume shared icon CSS sizing; remove scattered lucide size literals for compatible control icons. Decorative illustrations/logo/avatar dimensions are separately named, not tied to control heights.

Textarea shares size naming/font/radius/padding/state; rows defaults3, explicit rows honored, vertical resize and minimum two-line box; no one-line32px forced height. Checkbox label interactive target32/40/48 and meaningful16/18/20 indicator tokens, disabled/keyboard/focus behavior preserved; do not add Radio/Switch now. Icon buttons/links default32 square and accessible name; dense chip clear must no longer shrink to16px. All default targets exceed WCAG2.2 target24px, with spacing and real hit testing;32px does not authorize overlapping invisible targets. Readonly applies only where native semantics exist.

Panel keeps title/children/className compatibility and gains optional density standard|compact and actions ReactNode, used by actual Customer Detail; standard padding uses spacing6, compact spacing4. Existing standard pages retain semantic Panel behavior. Overlay keeps native modality/className layout slot, with canonical surface spacing/radius/elevation; no new Drawer/trap. StatusBadge keeps boolean|null and automatic height with semantic status text/spacing; no forced32px badge. Reduced-motion disables relevant transitions/animations without affecting readiness logic.

Semantic type roles: page title→xl/bold/tight; section heading→md/semibold/snug; body→base/normal/normal; small body→sm/normal/normal; label→base/semibold/snug; caption/table heading/status→sm with matching medium/semibold and snug; button label→base/semibold/snug. Aliases reference existing font/weight/line-height tokens. Space rules: controls gap2, fields gap2 and groups4, toolbar gap2/padding3, card/section padding4 or6, table cell inline3/block2, dialog header/body/footer4, pagination3. Genuine coordinates stay local; shared visual defaults do not.

### B. Runtime override and compatibility

Public size tokens live at root; changing one variant changes only that variant across actual Button/Input/Select/Checkbox target/compatible icons. Public radius/font overrides propagate across all compatible families. Private mappings are resolved where consumed, preventing feature inheritance from masking root updates. Remove Customer local sizing/font/radius and interactive-state overrides; migrate to shared variants. Preserve documented standalone Panel/Badge behavior explicitly; do not invent broad fallback permissions.

Existing old-token tests must first characterize the actual cascade failure (root height40 vs actual32), then migrate to the approved authoritative size token. New tests read baseline, apply a different value, assert every actual consumer equals override and differs from baseline, verify other size variants unaffected, and restore both value/priority plus computed baseline. Detached-consumer and wrong-priority negatives must fail.32/40/48 are now owner-defined acceptance values, not incidental defaults; test them exactly alongside dynamic override tests. Do not relax contrast, security, discovery or runtime assertions to accommodate the API migration.

### C. Customer generic reads and scoped statistics

Keep useCustomerRead<T> generic. Retain keyed last successful data and explicit request/generation metadata for same-key refetch, error and settlement; a changed key cannot expose old data as current. Invalidation immediately fences/aborts the old lane, even before the300ms URL commit. The List composition accounts for pending search draft when deciding display compatibility. Do not add a generic query cache/store or Customer-specific stats logic to this hook. Detail's retained data/reconciliation remains explicitly stale and retry-gated; no double-source success claim.

List stores one memory-only stats snapshot {stats,scopeKey,epoch,freshness,requestGeneration}. scopeKey uses verified workspace owner lifecycle plus canonical q/phone; excludes status/page/pageSize. customerStats validates backend nonnegative integers and sum. Capture only an accepted successful current generation; missing/malformed stats is unavailable. No page-row totals, pagination.total substitution, detail fan-out or stats-only request.

Loading uses five real tr rows × nine td Skeleton placeholders aligned to the same colgroup. Placeholder shapes are aria-hidden; table aria-busy and a single loading status announce progress. ### E. Shared Toast and API outcomes

Add minimal domain-neutral ToastProvider/useToast/Toast to packages/ui using React context, no dependency. Typed enqueue({id,tone,message}) and dismiss(id)/clear API; tones success|error|info. Message is a safe string, not raw server HTML/error payload; no provider/customer imports or transport. Render a semantic live region without stealing focus; add a neutral ToastViewport inside an open Overlay through optional Toast context, with exactly one active viewport (latest open modal, otherwise workspace). The same bounded provider queue moves between these surfaces on open/close, so errors are visible and dismissible within the native top layer/inert boundary. Overlay without a provider retains existing behavior. No ReactDOM portal or new dependency is needed; test registration, closure, unmount and duplicate live-region prevention. Use fixed placement within the active surface; explicit32px dismiss target. Error role alert, success/info role status; dedupe by stable operation/request-generation IDs, not rerenders. Max3 visible/6 queued with deterministic eviction of old success/info first; essential errors also remain inline. Error notifications persist until dismissal; transient success timers pause for hover/focus/hidden document; cleanup on unmount. Reduced-motion and keyboard dismissal mandatory.

Mount provider at the authenticated workspace boundary keyed by verified user identity, not as a new LayoutProvider/global store. This supports List, Detail/forms and future actual workspace callers while clearing notifications on logout/identity change. Login/MFA retain their existing essential authentication feedback and behavior; this task changes their sizing, not their error/session policy.

Customer owns request→safe-message classification via existing customerError. Initial/tab read failure: one Toast plus recoverable inline error/Retry. Same-query refresh failure: stale matching rows+Toast+inline Retry. Mutation failure: one error Toast and retained draft/field errors. Committed mutation: success Toast where useful; subsequent read failure is separately identified reconciliation failure, never rewritten as failed mutation.401 uses existing redirect,403 remains forbidden; safe400/404/409 details and requestId policy preserved. Do not double-announce identical Toast and inline live alerts; inline descriptions remain accessible without another redundant live region. No auto retry/toast loops.

### F. Table-wide Power single-flight and settlement

One synchronous ref lock in List is the authoritative write gate; togglingId is display only. Lock before any await/state batching; disable every Power button while any Power write is active, aria-busy/spinner only for active row, accessible state/name. Handler rechecks lock and current ownership/query lifecycle. Share existing safe error classifier and mutation policy; do not create a generic mutation framework. No optimistic status/counter changes. Same-tick A then B must send exactly one PATCH.

Separate mutation result from read settlement. After confirmed PATCH success, mark affected snapshot stale and initiate current-key list refresh; keep all Power actions unavailable until matching fresh read success OR explicit recoverable read failure. Generic read exposes monotonically identified accepted settlement, not await void. On read failure, release mutation lock but keep rows flagged stale and Power unavailable until explicit reconciliation Retry succeeds; announce committed mutation and failed refresh distinctly. Mutation rejection releases lock, preserves server-rendered status and classifies401/403/409 safely; ambiguous network failures require reconciliation before another write. Late/unmounted completion cannot unlock another operation or commit a stale query; no automatic PATCH retries. Create/Edit also invalidate affected stats and rows using existing successful callbacks.

## 9. Compatibility, risk and rollback

This is an intentional frontend breaking visual/type migration within a private same-revision workspace: size omission32, native numeric size no longer accepted by shared Input/Select, --control-height retired. Update every actual UI/Web caller/test together, publish size types, and document migration examples. No external consumer contract was found. Do not preserve44px fallback or weaken tests simply because old assumptions referenced it. Mitigations are explicit mappings, keyed lifecycle/dedupe, parser ownership tests and genuine ten-width measurements. Roll back focused frontend stage commits together with affected tests/docs if required; never revert security gates, mutate data/keys or reset volumes. Assess native modal/provider stacking with real browser before acceptance.
