# Testing

`sh scripts/quality-docker.sh` starts development mode, then runs frozen-installed formatting, architectural lint, typecheck, meaningful unit tests, contract drift, build and migrated PostgreSQL integration inside Docker. It pauses API/web watchers while build outputs are rewritten, restarts them on exit and does not delete volumes. Use the `run` mapped-user entrypoint for commands writing generated outputs rather than bypassing it with exec.

```sh
docker compose -f compose.yml -f compose.dev.yml run --rm --no-deps -T api sh /workspace/scripts/api-entrypoint.sh sh -c 'NODE_ENV=production API_INTERNAL_URL=http://api:4000 pnpm quality && NODE_ENV=test pnpm test:integration'
sh scripts/runtime-smoke.sh
sh scripts/data-smoke.sh
sh scripts/dev-smoke.sh
```

Runtime smoke creates its own disposable project and checks real proxy health/errors, non-root runtime, DB outage, repeated migration, and the complete authentication lifecycle (Host header filtering, untrusted Origin rejection, unauthenticated route rejection, safe malformed cookie parsing, login credential verification, session cookie issuance, session validation, and post-logout revocation). Data smoke stores a real catalog row + file, verifies down/up and service restart persistence in distinct disposable volumes, then removes ONLY those volumes. Dev smoke verifies HMR/shared propagation and frozen dependency failure without resetting DB. Stop unrelated web occupying port 3001 first.
Host `pnpm quality` is optional and needs working engine downloads; it is not a substitute for Docker runtime verification. Contracts can generate without DB or engine; built web consumes existing generated output.
CI `.github/workflows/foundation.yml` runs Docker quality/runtime/data/dev smoke on Linux. A created workflow is NOT VERIFIED until a hosted run exists. See the task ledger for actual commands, counts and limitations.

Cloud-only overrides may be supplied as `NEXORA_COMPOSE_OVERRIDE=/absolute/path/platform.yml`. Set `NEXORA_QUALITY_NO_BUILD=1` only when matching dev/migration images were already built and verified; the default builds images. Neither option skips quality or integration checks.

The authentication runtime smoke now provisions fresh operators through `dist/cli/user-create.js --password-stdin` via the runtime entrypoint, verifies duplicate rejection, and runs `scripts/provisioning-tty-smoke.py` against the same compiled non-root image. The pseudo-TTY harness uses Python standard-library PTY facilities, checks hidden password/confirmation, Enter, Backspace, Ctrl+C/Ctrl+D and both container/host terminal restoration without printing captured output.

`scripts/auth-runtime-smoke.mjs` exercises the actual Web proxy: exact/missing/wrong Origin, invalid JSON fields, fake/malformed/expired sessions, cookie attributes under forged forwarding headers, persistence across API restart, idempotent logout, safe logout failure and fail-closed workspace access during a disposable PostgreSQL outage followed by recovery. It additionally asserts standalone public `/login` rendering (no AppShell), unauthenticated/stale session redirection (`/login?from=...`), and valid session workspace access. `scripts/browser-login-smoke.mjs` uses Chromium DevTools with Node's built-in WebSocket to verify standalone Login layout (no AppShell headers/navigation), unauthenticated workspace redirection, typing and submitting the real Login form, observing the response, verifying HttpOnly session and authenticated AppShell presence on protected navigation, and post-logout revoked session redirection. It adds no npm browser framework. Host smoke requires Node >=22, Python 3 and installed Chrome/Chromium (or CHROME_BIN); missing browser support fails instead of silently skipping. Existing foundation CI selects pinned host Node 24.19.0 and invokes these through runtime smoke. Credentials arrive by stdin and are never emitted in diagnostics.

`NEXORA_COMPOSE_OVERRIDE` also applies to runtime smoke, allowing the same cloud CA build-secret setup as quality. Run with a different loopback WEB_PORT to exercise port derivation without publishing API/database. All destructive expiry/outage/cleanup steps are limited to the disposable project's own data. Source changes and historical CI do not establish that these expanded checks passed; current evidence and gaps remain in NEXORA-009.

Authentication HTTP smoke uses stable diagnostic step IDs with only expected/actual status and sanitized failure categories. The Host-negative check uses `node:http`, because Node 24 fetch rewrites Host and cannot establish that an untrusted Host reached middleware. No response payload, cookie/token, request body or raw assertion/driver exception is printed. `pnpm test:operations`, included in quality, exercises this transport and smoke check diagnostics behavior.

The database migration suite runs `pnpm --filter @nexora/database test:migrations` inside canonical quality. It creates only owned UUID-named databases, deploys authentic historical Prisma migrations, injects a failure into a temporary migration/config to verify rollback and Prisma recovery, then checks forward deployment, constraints, preservation, repeatability and drift. Historical provider-schema checks are upgrade fixtures; they do not imply provider login is supported.

Current integration uses `integration.test.cjs`, `identity-concurrency.test.cjs`, `user-status-http.test.cjs` and `legacy-session-cutover.test.cjs`. Coverage includes local ADMIN/OPERATOR login, missing credentials, real SessionGuard status/expiry/revocation, atomic CLI provisioning, session-issuance hash/status races, token consume/reissue/disable races and last-admin serialization. Some generic session tests insert credentialless session rows directly as test fixtures; this is not an authentication issuance path or evidence that legacy provider sessions may survive cutover.

`user-status-http.test.cjs` starts real NestJS against its own migrated PostgreSQL database. It checks GET 401/403/200 and exact seven-field summaries; PATCH 401/403, missing/invalid Origin, invalid status and extra role/fields (400 VALIDATION_ERROR), missing user (404 NOT_FOUND), self/other-admin disable, last-admin 409, OPERATOR session/setup-token revocation, reactivation without resurrection and two simultaneous HTTP self-disable requests (one 200, one 409 LAST_ACTIVE_ADMIN). Assertions cover status, error code/envelope/request ID, summary fields and committed database effects. Existing adapter transaction races remain separate.

`legacy-session-cutover.test.cjs` uses genuine staged Prisma deployments and the real session adapter/service to reproduce the pre-PR2 provider-session gap, with local ADMIN/configured OPERATOR/DISABLED/file controls. The owner-approved sixth migration then deletes valid/expired credentialless OPERATOR sessions, preserves ADMIN/configured OPERATOR sessions and application data, rejects disabled users, and proves old tokens remain invalid after actual password setup while new local login succeeds. Repeated deploy preserves the fresh local session. The database package migration suite independently checks selective revocation, user/credential/file preservation and schema drift.

Carrier unit coverage is `apps/api/test/carrier-uniship.test.cjs`: independent Uniship client/parser URL/HTTPS, live-call gating, payload/userid/is_verified validation, safe HTTP errors, timeout and redirect rejection using local mocks. Config tests retain environment normalization. There is no `provider-auth.test.cjs`, Identity provider-auth orchestration, provider registration SQL or Employee/Admin login-mode suite. Historical NEXORA-012 results remain in its task record only. The current browser harness tests one local Nexora form and fragment setup. No test calls live Uniship.

`node --test apps/web/test/launcher.test.mjs` is included in the Web package test command and canonical quality. It exercises the real dev/start entrypoints against a disposable Next CLI fixture, using randomly allocated ports. Coverage includes canonical host/Docker/custom port parsing and boundaries; malformed/empty PORT; command/argument/environment propagation; normal/nonzero/signal child exit codes; sanitized actual spawn failure; occupied-port refusal without fallback or damage to the existing listener; a real EADDRINUSE after preflight; and SIGINT/SIGTERM/SIGHUP forwarding, child exit and released ports. These focused process tests supplement real Next.js HMR/runtime/browser smoke rather than replacing it.

## Logical PR 2 identity verification

`apps/api/test/identity-concurrency.test.cjs` creates a new UUID-named PostgreSQL database, deploys real Prisma migrations and exercises both-role login, delayed-verification hash/status changes, token replay/expiry/non-overwrite, consume/consume, consume/reissue, consume/disable and last-two-admin races using independent connections. A trigger-induced revocation failure proves transaction rollback. HTTP checks cover RBAC, safe summaries, Origin and removed provider route. Only the owned test database is dropped. The migration suite separately preserves legacy user/credential/session/file snapshots, deploys the forward migration, checks token constraints and repeated-deploy drift. No fabricated Prisma history or schema push is used.

Browser smoke exercises one local form, actual fragment setup/URL clearing, no token in request URLs/Referer/SSR/browser storage or captured API/Web server logs, no auto-login and subsequent OPERATOR local login. Carrier transport/parser tests retain loopback mock safety coverage; no live Uniship call is authorized by tests. Canonical quality/runtime/data/dev scripts run in disposable Compose projects. Native engine-download restrictions must be reported separately from executed hosted CI evidence.

Canonical quality also runs `python3 scripts/dev-cleanup-smoke.py`, which executes the actual optional cleanup SQL through psql in an unpublished, disposable PostgreSQL container. It verifies default dry-run, environment/database/prefix/confirmation rejection and preservation of administrators and configured operators. Raw committed DDL in this maintenance-only harness is not Prisma migration metadata evidence.

## Persisted vocabulary quality gate

`pnpm lint` retains the existing boundary checker and ESLint rules and enables the local error-level `nexora/no-domain-vocabulary-literals` AST rule (`scripts/eslint-rules/no-domain-vocabulary-literals.mjs`). Scope is `apps/api/src/{identity,carrier}/**/*.ts`, including infrastructure/application; `test`, `tests`, `__tests__` directories, `*.test.ts`, `*.spec.ts`, `*.d.ts` and globally ignored generated outputs are excluded. SQL migrations, JSON/OpenAPI, SDK generated files and Markdown are outside this guard. No new dependency or runtime registry is introduced.

It detects known persisted values only with status/role/provider/secretType/secret_type context: object metadata/writes, nested Prisma in/notIn/equals/not filters, comparisons in either direction, variable/member assignments, array includes, conditional branches, TypeScript expression wrappers and static template strings. ERROR requires an explicit connection context (connection.status, direct connection object, or carrierConnection model operation); unrelated transport status ERROR and error codes remain valid. Canonical declaration keys differ from domain field names and are accepted without exempting entire domain files; an arbitrary as-const object containing status ACTIVE is still rejected. Arbitrary aliases, dynamic keys, type-only literals and embedded SQL text are not inferred; manually audit those against the canonical owner. This bounded syntax rule does not claim type-checker-level semantic coverage.

`pnpm test:lint` runs actual ESLint RuleTester with the TypeScript parser, real configuration scope/exclusion tests, a canonical-vocabulary coverage test reading owning declarations via TypeScript AST, and a real CLI probe. The probe creates only its own unique source fixture, requires CLI exit 1 plus this rule ID for a violation, replaces it with a canonical import and requires exit 0, then removes the fixture. It does not edit user files. Canonical `pnpm quality` runs test:lint immediately after lint, so existing quality-docker.sh and foundation CI execute both the source gate and its automated tests. No boundary rule is replaced or disabled.
