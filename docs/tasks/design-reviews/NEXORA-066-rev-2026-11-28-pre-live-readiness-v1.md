## 9. Unresolved PLAN ISSUE (Gate-Opening Prerequisite)

- **Location**: `apps/api/src/sync/infrastructure/uniship-sync.runtime.ts` (`authorize`, lines 40–61, specifically line 45 `if (!policy) return;`) paired with `apps/api/src/carrier/infrastructure/uniship/uniship-http.client.ts` (`operationallyAvailable`, lines 266–273).
- **Current Safety**: Safe on `a4ccfaf` solely because `UNISHIP_LIVE_CONTRACT_VERIFIED: boolean = false` causes `UnishipHttpClient.target()` (lines 433–444) to fail closed with `503 SERVICE_UNAVAILABLE` for all non-loopback targets regardless of `UNISHIP_LIVE_AUTHORIZED` or `UNISHIP_ACTIVATION_POLICY_JSON`.
- **Concrete Hazard Once Gate Opens**: When a future gate-opening PR changes `UNISHIP_LIVE_CONTRACT_VERIFIED` to `true`, if an environment deploys with `UNISHIP_API_URL=https://kh.uniship.vn` and `UNISHIP_LIVE_AUTHORIZED=true` while `UNISHIP_ACTIVATION_POLICY_JSON` is blank (`policy === undefined`), `operationallyAvailable()` returns `true` and `authorize(scope)` returns without validating owner/account/login scope — permitting `POST /api/carrier-connections` and `POST /api/carrier-connections/:id/reconnect` (Carrier interactive routes) to dispatch external live Uniship HTTP requests for any user without account-scoped policy, even when `SYNC_ENABLED=false`. (`SyncRepository` stays closed via `settings.activation !== undefined`, so only Carrier connect/reconnect is exposed).
- **Required Fix in Next Gate-Opening PR**: Require non-blank `UNISHIP_ACTIVATION_POLICY_JSON` in `authorize(scope)` whenever the outbound Uniship target is non-loopback (`UNISHIP_API_URL` is external), OR require `UNISHIP_ACTIVATION_POLICY_JSON` whenever `UNISHIP_LIVE_AUTHORIZED=true`, preserving legacy loopback test fixtures without regression.
