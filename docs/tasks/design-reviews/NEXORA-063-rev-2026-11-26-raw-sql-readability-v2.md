## 2. Requirements & Scope Reduction Decision

- **Owner Decision (2026-11-26)**:
  PR #62's sole intended purpose is making production Raw SQL readable for review without altering the actual SQL sent to PostgreSQL. Prior ORM conversions, mappers (`shipment-read.mapper.ts`, `sync-job.mapper.ts`), and ORM-specific test/benchmark changes from historical HEAD `8a7b7e4` are removed.
- **In-Scope Items**:
  1. Format all production Raw SQL (`apps/api/src`) as readable multiline parameterized template literals (uppercase SQL keywords, one `SELECT` column / `WHERE` condition / `SET` assignment per line, clear `WITH` / `RETURNING` blocks, lines `<= 120` chars).
  2. Extract long (> ~15 formatted lines) or reused SQL builders into pure `queries/*.queries.ts` functions returning `Prisma.Sql` from explicit SQL parameters (no client/transaction creation, no full domain objects).
  3. Add one-line "why" invariant comments for locks (`FOR UPDATE` / `FOR SHARE` / `SKIP LOCKED` / `pg_advisory_xact_lock` / `sync_lock_*`), lease fencing (`lease_version`, `worker_id`, `lease_expires_at`), `clock_timestamp()`, and lock ordering.
  4. Add ESLint rules `nexora/no-unsafe-raw-sql` and `nexora/readable-raw-sql` with RED/GREEN tests (`pnpm test:lint`).
  5. Prove normalized SQL parity against `origin/main` (`5edbcfe`) in `docs/tasks/evidence/NEXORA-063/`.
- **Explicit Non-Goals**:
  - Zero Raw SQL → Prisma ORM conversions, zero new mappers, zero `SELECT *` → column-list rewrites, zero schema/migration/contract/DTO/grant/timeout/business-logic changes.

## 4. Mandatory Reuse & Design Audit Matrix

| Field                        | Raw SQL Presentation & Guardrails                                                                                                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Component**                | Multiline Raw SQL formatting, `queries/*.queries.ts` builders, invariant comments, `nexora/no-unsafe-raw-sql`, `nexora/readable-raw-sql`                                                                            |
| **Existing implementations** | `shipmentReconciliationQueries` (`shipment-reconciliation.ts`), `scanIdentityResolutionQuery` (`sync-scan-observation.ts`), `scripts/eslint-rules/no-domain-vocabulary-literals.mjs`                                |
| **Domain owner**             | Owning module infrastructure (`shipment/infrastructure/queries/`, `sync/infrastructure/queries/`); ESLint rules in `scripts/eslint-rules/`                                                                          |
| **Reuse alternatives**       | Alternatives rejected: Prisma ORM conversion (alters generated SQL and adds mapper/parity risk), external SQL formatter plugin (unnecessary dependency), generic query repository (forbidden by `PROJECT_RULES.md`) |
| **Selected approach**        | Pure multiline formatting + conditional extraction to `queries/*.queries.ts` + invariant comments + local AST/layout ESLint rules                                                                                   |
| **Rationale**                | Zero SQL semantic drift, zero new runtime dependencies, automated prevention of future single-line or unsafe raw SQL                                                                                                |
| **Risks**                    | Accidental SQL token/cast/whitespace-sensitive drift during formatting                                                                                                                                              |
| **Verification**             | Automated normalized SQL parity script (`docs/tasks/evidence/NEXORA-063/`), `pnpm test:lint`, `pnpm quality`, genuine PostgreSQL CI                                                                                 |
