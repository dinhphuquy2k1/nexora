# Testing

`sh scripts/quality-docker.sh` starts development mode, then runs frozen-installed formatting, architectural lint, typecheck, meaningful unit tests, contract drift, build and migrated PostgreSQL integration inside Docker. It pauses API/web watchers while build outputs are rewritten, restarts them on exit and does not delete volumes. Use the `run` mapped-user entrypoint for commands writing generated outputs rather than bypassing it with exec.

```sh
docker compose -f compose.yml -f compose.dev.yml run --rm --no-deps -T api sh /workspace/scripts/api-entrypoint.sh sh -c 'NODE_ENV=production API_INTERNAL_URL=http://api:4000 pnpm quality && NODE_ENV=test pnpm test:integration'
sh scripts/runtime-smoke.sh
sh scripts/data-smoke.sh
sh scripts/dev-smoke.sh
```

Runtime smoke creates its own disposable project and checks real proxy health/errors, non-root runtime, DB outage, repeated migration, and the complete authentication lifecycle (Host header filtering, untrusted Origin rejection, unauthenticated route rejection, safe malformed cookie parsing, login credential verification, session cookie issuance, session validation, and post-logout revocation). Data smoke stores a real catalog row + file, verifies down/up and backup/restore in distinct disposable volumes, then removes ONLY those volumes. Dev smoke verifies HMR/shared propagation and frozen dependency failure without resetting DB. Stop unrelated web occupying port 3001 first.
Host `pnpm quality` is optional and needs working engine downloads; it is not a substitute for Docker runtime verification. Contracts can generate without DB or engine; built web consumes existing generated output.
CI `.github/workflows/foundation.yml` runs Docker quality/runtime/data/dev smoke on Linux. A created workflow is NOT VERIFIED until a hosted run exists. See the task ledger for actual commands, counts and limitations.

Cloud-only overrides may be supplied as `NEXORA_COMPOSE_OVERRIDE=/absolute/path/platform.yml`. Set `NEXORA_QUALITY_NO_BUILD=1` only when matching dev/migration images were already built and verified; the default builds images. Neither option skips quality or integration checks.

The authentication runtime smoke now provisions fresh operators through `dist/cli/user-create.js --password-stdin` via the runtime entrypoint, verifies duplicate rejection, and runs `scripts/provisioning-tty-smoke.py` against the same compiled non-root image. The pseudo-TTY harness uses Python standard-library PTY facilities, checks hidden password/confirmation, Enter, Backspace, Ctrl+C/Ctrl+D and both container/host terminal restoration without printing captured output.

`scripts/auth-runtime-smoke.mjs` exercises the actual Web proxy: exact/missing/wrong Origin, invalid JSON fields, fake/malformed/expired sessions, cookie attributes under forged forwarding headers, persistence across API restart, idempotent logout, and safe logout failure during a disposable PostgreSQL outage followed by recovery. `scripts/browser-login-smoke.mjs` uses Chromium DevTools with Node's built-in WebSocket to type into and submit the real Login form, observe the response, verify HttpOnly session and protected navigation, then logout. It adds no npm browser framework. Host smoke requires Node >=22, Python 3 and installed Chrome/Chromium (or CHROME_BIN); missing browser support fails instead of silently skipping. Existing foundation CI selects pinned host Node 24.19.0 and invokes these through runtime smoke. Credentials arrive by stdin and are never emitted in diagnostics.

`NEXORA_COMPOSE_OVERRIDE` also applies to runtime smoke, allowing the same cloud CA build-secret setup as quality. Run with a different loopback WEB_PORT to exercise port derivation without publishing API/database. All destructive expiry/outage/cleanup steps are limited to the disposable project's own data. Source changes and historical CI do not establish that these expanded checks passed; current evidence and gaps remain in NEXORA-009.

Authentication HTTP smoke uses stable diagnostic step IDs with only expected/actual status and sanitized failure categories. The Host-negative check uses `node:http`, because Node 24 fetch rewrites Host and cannot establish that an untrusted Host reached middleware. No response payload, cookie/token, request body or raw assertion/driver exception is printed. `pnpm test:operations`, included in quality, exercises this transport and restore orchestration guards/order/failure behavior.

Data smoke also invokes `scripts/auth-restore-smoke.mjs`: it provisions through the real CLI, backs up a live session, revokes it at source, restores to a different loopback port, requires exact old-token 401, and verifies unchanged operator identity/new Login. Another live source session proves restore invalidation is target-only. A historical schema fixture deployed by the real Prisma runner produces authentic migration metadata before backup; current restore applies missing auth migration, verifies no assumed accounts, and provisions the first operator via CLI. Existing file/corruption/overwrite assertions remain. These end-to-end claims require real Docker execution; orchestration mocks prove only command ordering and fail-closed behavior.
