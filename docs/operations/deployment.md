# Deployment scope

IMPLEMENTED target: local, single-machine, loopback web exposure only (`http://127.0.0.1:3001`). Local authentication, Scrypt operator credentials, and opaque PostgreSQL sessions are implemented under [ADR-005](../decisions/authentication.md). Public TLS, remote access policy, managed key storage, scaling, rollout/rollback, or public production topology have not been selected for baseline. Do not expose this foundation on the Internet without completing the PR 7 release gates.
Distribution template pins application tags 0.1.0, but those images are NOT PUBLISHED; `--prebuilt` cannot be promised to users. Task only builds local images. Registry publication, signed release/digests and a verified Windows/macOS distribution are future explicit release tasks.
Local database uses persistent generated credentials, not shared committed passwords. Volume snapshot/backup is separate from image build. Restart must not rotate credentials or remove data. CI runtime smoke is evidence for local release semantics, not proof of production hosting readiness.

## Public HTTPS Deployment & MFA Release Gates (PR 7)

Under [ADR-007](../decisions/multi-carrier-architecture.md), public deployment of Nexora is planned for PR 7 subject to the following gates:

1. **Mandatory PR 6 Prerequisite**:
   - Every ADMIN account must have completed TOTP enrollment via `pnpm mfa:enroll` prior to public exposure.
   - The application runtime enforces this at boot: if public profile is enabled and MFA enforcement is disabled, the API process refuses to start.
2. **TLS Ingress & Network Hardening**:
   - Public TLS termination must provide modern cipher suites and HTTP/2 or HTTP/3.
   - Host Header and CORS/Origin allowlists must be strictly configured in server configuration.
   - Ingress reverse proxy must pass client IP only through trusted proxy subnet configuration (`trust proxy`).
3. **Host Clock NTP Synchronization**:
   - Because Docker containers inherit the host kernel clock and TOTP requires time accuracy within ±30 seconds, the host must run an active NTP daemon (`chrony` or `systemd-timesyncd`).
   - Runbook verification command on the Linux host:
     ```bash
     timedatectl status
     ```
     Deployment requires `NTP service: active` and `System clock synchronized: yes`.
4. **Remote Operator Onboarding**:
   - Remote operators receive a single-use, cryptographically secure onboarding setup link generated by an administrator.
   - The setup link is valid for a short duration (e.g. 24 hours), consumed atomically, and allows the operator to set their initial password directly over HTTPS without the administrator ever seeing or handling their credentials.

## Logical PR 2 local identity rollout

Deploy the new `20261015000000_local_identity_onboarding` migration forward without editing history or resetting volumes. It preserves valid local users, credentials, sessions and stored files, adds hashed setup tokens and removes legacy provider bindings. Both ADMIN and OPERATOR use Nexora local login; credentialless retained operators require ADMIN-issued setup links. The legacy provider route returns 404; Uniship configuration cannot affect local sessions. Administration remains loopback-only until the separately planned MFA/HTTPS milestones. Setup links are sensitive, expire after 24 hours and must be delivered privately. Optional development cleanup is manual and guarded; see [Setup](setup.md).

The owner-approved PR 2 follow-up migration `20261015010000_legacy_provider_session_cutover` intentionally narrows blanket session preservation: every OPERATOR session without a local credential is revoked, regardless of status/expiry; ADMIN and configured OPERATOR sessions remain. Stop API/Web and provisioning writers during upgrade. Account/file data remains, old cookies never revive after setup, and no authentication-source distinction is available for configured operators. See [Setup](setup.md) and ADR-007.

## PR18 database authority cutover — NEXORA-019

Deploy matching tooling/migration/API images with the updated Compose dependency chain: init → PostgreSQL healthy → migrate (nexora admin) → db-runtime (trusted role provisioner) → API (nexora_app) → Web. Stop writers before upgrade and retain existing data/admin credential volumes. Add runtime_credentials; never rotate the bootstrap password to introduce runtime isolation. API mounts only its dedicated runtime secret read-only; Web mounts neither. compose.release.yml mirrors custody but remains an unpublished image template, not verified public hosting.

Role provisioning is idempotent and fail-closed on unsafe role/custody conflicts. Refer to Setup for administrator recovery. Existing audit trigger remains enabled; runtime SQL cannot disable/drop it or mutate audit, while privileged administration/host access remains outside the guarantee. External Uniship, public HTTPS and MFA release gates are unchanged.

## PR6 local MFA cutover — NEXORA-022

Deploy matching ninth-migration/runtime images with writers stopped, retain all volumes, supply dedicated Identity keys, run genuine migrate then explicit restricted runtime grants, enroll administrators via the one-off interactive API CLI, and only then start new API/Web. The detailed ordered runbook and fresh-install command are in Setup. There is no temporary HTTP enrollment or privileged password bypass. Existing PASSWORD session rows are preserved by migration but globally denied admin capability; enrollment revokes them. User/credential/Carrier/audit/files remain intact. Update of Identity key custody requires restart and retention of old versions; no automatic re-encryption/reset exists.

This implements mandatory ADMIN MFA for the current local deployment only. Public TLS, ingress, public boot release gates and PR7 readiness remain PLANNED. No deployment command should expose Web beyond loopback or unlock live Uniship traffic.
