## Definitions and calculation

- Initial ingress start means the main service start before first browser, not missing-TLS one-off or later explicit restore/restart. Failed buffers retain that lifecycle; PASS final buffers retain later starts only. See scripts/public-https-smoke.sh:109–116,132–137,151–164 and prior lifecycle evidence.
- Literal Δ1 is the last retained veth ADDR/ROUTE **anywhere after initial ingress start** minus that start. This includes cleanup events, so is not an initial network-settle measurement. Report separately from Δ1 early, whose last event is between initial start and recorded failure. No silent removal of later events.
- Request window intersection: [request start, terminal time] intersects [event−100ms,event+100ms]. Also report whether request is actually in flight at the exact event instant. A completed successful request within100ms is not a request canceled at that event.
- first retained request is the earliest diagnostic request, not necessarily the first browser request: the transport observer retains fixed auth/operator endpoints and failed Next Script observations, not all navigations/assets. First actual browser request is NOT VERIFIED in every sample. Script start is reconstructed as failedUTC−elapsedMs (rounded durations).
- scripts/public-https-diagnostics.mjs:639–647 and scripts/public-https-environment.mjs:15–25 retain rolling200-event projections; successful browser transport is not persisted as failure.json. No interface identity/address family, tentative/permanent flag, or DAD state retained. Thus veth does not establish ingress ownership or IPv6 DAD.
