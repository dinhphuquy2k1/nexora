# Configuration

Compose supplies defaults and an idempotently generated local database credential, stored in a dedicated volume. Never print its contents or commit it. This credential is for isolated local PostgreSQL, not public deployment.

| Variable                | Owner / contract                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DATABASE_URL            | API/migration server only; required PostgreSQL URL; entrypoint reads credential file and injects URL                                                                                                                                                                                                                                                                    |
| STORAGE_ROOT            | API only; canonical absolute root, default /data/uploads in runtime, precreated writable volume                                                                                                                                                                                                                                                                         |
| PORT                    | API, 1..65535, default 4000                                                                                                                                                                                                                                                                                                                                             |
| WEB_PORT                | Compose Web binding, default 127.0.0.1:3001; also passed to API for Origin resolution. Supported derived values: bare port or loopback host:port.                                                                                                                                                                                                                       |
| POSTGRES_PORT           | Docker Compose development only (`compose.dev.yml`); optional numeric host port for PostgreSQL loopback publishing; default 5432; strictly bound to `127.0.0.1`. Never published in standard release mode (`compose.yml`).                                                                                                                                              |
| NODE_ENV                | development/test/production, runtime production                                                                                                                                                                                                                                                                                                                         |
| API_DOCS_ENABLED        | API, explicit true/false, defaults false                                                                                                                                                                                                                                                                                                                                |
| API_INTERNAL_URL        | Next.js server (`lib/api/config.ts`); required origin URL without path/query/fragment; supplied explicitly by Compose (`http://api:4000`) and `.env.example`; no application-level fallback; never NEXT_PUBLIC                                                                                                                                                          |
| ALLOWED_HOSTS           | Web ingress middleware only; optional comma-separated host allowlist (defaults: localhost, 127.0.0.1, 0.0.0.0)                                                                                                                                                                                                                                                          |
| ALLOWED_ORIGINS         | API only; optional comma-separated exact HTTP(S) origins. Replaces defaults; invalid values fail startup. Without it, trusted HTTP localhost/127.0.0.1 origins derive from WEB_PORT.                                                                                                                                                                                    |
| UNISHIP_API_URL         | API only; optional base URL for provider authentication adapter (local mock provider in tests; application default remains unconfigured; `.env.example` actively supplies `https://kh.uniship.vn`). Never exposed to client. Forwarded by Compose (`"${UNISHIP_API_URL:-}"`). Empty string normalizes to `undefined` so omitted configuration never breaks API startup. |
| UNISHIP_LIVE_AUTHORIZED | API only; explicit boolean flag (`true`/`false`, default `false`). Blocks live/external provider calls unless explicitly set; live integration fails closed when false. Forwarded by Compose (`"${UNISHIP_LIVE_AUTHORIZED:-false}"`).                                                                                                                                   |

Swagger is not exposed by default. Config errors fail startup with safe JSON diagnostics. Missing or invalid `API_INTERNAL_URL` fails explicitly at build and startup time with an actionable error. Reference `.env.example` documents environment variables for local inspection. When `UNISHIP_API_URL` is omitted or empty, the API starts normally and ADMIN local login remains fully functional, while employee provider Login (`POST /api/auth/provider/login`) returns HTTP 503 `SERVICE_UNAVAILABLE` fail-closed. The owner confirmed Uniship API integration authorization on 2026-10-13. `UNISHIP_LIVE_AUTHORIZED` remains an operational enablement switch, default `false`; the administrator may explicitly set it to `true` under the approved authorization and deployment procedure. The operator is responsible for configuring the correct `UNISHIP_API_URL`; existing environment-driven URL behavior remains unchanged, with no additional destination allowlist or hardcoded production URL. Production HTTPS, timeout, redirect rejection, payload validation, safe errors and provider token non-persistence still apply. Local mock-provider PASS does not prove real Uniship authentication; live verification remains deferred. Testing against local mock providers uses isolated test endpoints without granting live authorization. No external carrier key is currently used. Future carrier provider keys remain server-side, encrypted when persisted; key management and public identity are separate milestones.

Browser mutation origins compare scheme, normalized hostname and effective port. Missing/null/multiple origins, credentials, whitespace, paths (including a trailing slash), queries and fragments are rejected. Configuration entries may be comma-separated with surrounding whitespace, but each entry must be an origin. Changing `WEB_PORT=127.0.0.1:3101` automatically trusts only the two loopback HTTP origins on port 3101; container-internal port 3000 is never implicitly trusted as a browser-facing origin. An explicit `ALLOWED_ORIGINS` replaces both defaults, so operators must include every intended browser-facing origin. API startup snapshots this policy; restart after configuration changes. Both Docker and host Web use canonical user-facing port 3001; Docker API remains private.

The supported deployment is loopback HTTP. Session and clearing cookies use `Secure=false`, `HttpOnly`, `SameSite=Lax`, and `Path=/`; raw forwarded headers and `req.secure` cannot select transport policy. Adding HTTPS/LAN hosting requires a separate deployment decision.

`.env.example` provides `UNISHIP_API_URL=https://kh.uniship.vn` as an active API **base URL**, not the `/client/api-token-auth/` endpoint path. Copying it to `.env` configures that example destination for Compose while keeping `UNISHIP_LIVE_AUTHORIZED=false`; it does not enable live requests. The deployment administrator must select the correct base URL and may override it via the environment. No provider credential/token belongs in the example. Omitting or emptying the URL retains the existing safe provider-unavailable behavior and independent ADMIN Login.

The Web package's `pnpm dev` and `pnpm start` share `scripts/lib/launch-next.mjs`: HOST defaults to `0.0.0.0`, and PORT defaults to 3001 only when absent. An explicitly empty PORT is invalid. Ports must be decimal integers 1–65535; suffixes, signs, fractions and whitespace are rejected. This PORT is the actual Next.js listener, distinct from Compose's WEB_PORT binding: Docker development explicitly supplies internal PORT 3000 while the published loopback port defaults to 3001. Docker release retains its existing direct Next.js CLI invocation and internal listener configuration.

In Docker development mode (`compose.dev.yml`), PostgreSQL automatically publishes host port `127.0.0.1:5432` for local database inspection tools (e.g. DBeaver, pgAdmin). The host address is permanently fixed to `127.0.0.1` in Compose configuration and cannot be bound to external network interfaces. `POSTGRES_PORT` modifies only the numeric host port (e.g. `5433`). In standard release mode (`compose.yml`), PostgreSQL has no published host port, and database traffic remains strictly internal to Docker bridge networking.
